# 영상 다음에 직접 해볼 실습

먼저 같은 조건으로 실행하고 결과를 확인한 다음, 한 조건만 바꿉니다. `prompts`의 텍스트 파일은 메모장이나 텍스트 편집기로 수정할 수 있습니다. 원본은 별도로 복사해 두세요.

## 1. 리뷰 기준 바꾸기

`prompts/02_reviews.txt`에서 낮은 평점 기준을 `1~2점`에서 `1점`으로 바꿉니다.

프로젝트 루트에서 `python3 course/run.py reviews`를 실행합니다. 고유 리뷰 120개와 중복 5개는 그대로여야 합니다. 1점 리뷰는 6월 15개, 7월 12개, 8월 15개로 총 42개입니다. 기존 1~2점 기준의 76개와 왜 다른지 설명해 보세요.

더 넓게 적용: 고객 문의, 설문 응답, 앱스토어 후기. 실제 자료에서는 중복을 구분할 ID와 개인정보 처리 범위를 먼저 정합니다. `topic_hint`가 없는 실제 리뷰의 의미 분류 정확도는 별도 검증해야 합니다.

## 2. 보고서 기준일 바꾸기

`prompts/03_weekly.txt`의 기준일을 `2026-09-09`로 바꿉니다.

`python3 course/run.py weekly`를 실행합니다. T-102의 기한은 9월 10일이므로 새 기준일에는 기한 경과로 분류하면 안 됩니다. T-103의 담당자, T-104의 기한, T-105의 업무 목록 등록 여부는 기준일을 바꿔도 달라지지 않습니다.

더 넓게 적용: 주문과 배송 목록, 교육 신청서와 참석자 목록, 행사 준비 업무와 회의록. 제목이 비슷하다는 이유로 ID가 다른 자료를 합치지 않습니다.

## 3. 조사 질문 바꾸기

`prompts/01_research.txt`에서 비교 항목을 하나 바꿉니다. 예를 들어 시작 안내 대신 파일 업로드 관련 안내가 있는지 확인하도록 요청합니다.

`python3 course/run.py research`를 실행합니다. 각 결론의 원문 링크를 열어 실제 안내가 있는지 확인하세요. 조회 실패를 기능이 없다는 뜻으로 해석하면 안 됩니다. 비교 항목과 근거가 맞지 않으면 답변이 그럴듯해도 성공으로 보지 않습니다.

더 넓게 적용: 행사 장소의 공식 안내, 교육 서비스 도움말, 제품 사용 설명서. 가격이나 영업시간 등 변동 정보는 조사 시점을 기록하고 현재 원문을 확인합니다.

## 4. 필요한 PR만 고르기

`prompts/04_github.txt`에 “목록에서 처음 3개만 골라 상세 조회하고 표로 정리해”를 명시합니다. 실습 도구의 목록 응답은 여전히 최대 5개이며, 모델이 그중 3개를 선택해야 합니다.

`python3 course/run.py github`를 실행합니다. 최종 표의 PR 번호가 실제 목록에 있는지 확인하고, 중복된 행이 없는지 봅니다. CI는 이 도구가 조회하지 않으므로 여전히 미조회입니다.

더 넓게 적용: 이슈 목록에서 우선순위에 맞는 항목 고르기, 변경 파일이 많은 작업 살펴보기. 조회 결과만으로 자동 승인이나 병합을 수행하는 실습은 아닙니다.

## 실습 성공의 기준

Code Mode 실행 코드가 실제로 남았는지와 결과가 정확한지를 따로 확인합니다. 입력 자료 전체를 다시 보여주는 답변보다, 검증 가능한 숫자·원문 ID·출처 링크가 있는 결과를 요구해 보세요. 조건을 바꿨는데 숫자가 그대로라면 실제 데이터에서 결과가 같을 수 있는지도 먼저 확인합니다.
